# Contributing

## Commit and PR Titles

Commit messages and PR titles must follow [Conventional Commits](https://www.conventionalcommits.org/) style.

Allowed types: `feat`, `fix`, `docs`, `doc`, `perf`, `refactor`, `style`, `test`, `chore`, `ci`, `revert`. Scope is
optional.

Type must reflect user-visible behavior, not implementation activity. CLI interface/behavior changes (commands,
flags/options, arguments, output contract, exit codes, documented usage) must be `feat`, `fix`, or `perf` (use `!` when
breaking), never `refactor`.

PR title enforcement and changelog decision tag validation are implemented in
`.github/workflows/conventional-commit-pr-title.yml`. Every PR body must contain exactly one of `changelog: include` or
`changelog: skip` to pass CI.

## Changelog

Changelog generation uses [git-cliff](https://git-cliff.org/) and the root `CHANGELOG.md`.

By default, only user-visible changes appear in the changelog (`feat`, `fix`, `perf`, `revert`). Non-user-visible types
(`refactor`, `style`, `test`, `chore`, `ci`, `docs`, `doc`) are excluded.

Override tags in the commit body can force inclusion or exclusion:

- `changelog: include` forces a commit into the changelog regardless of type.
- `changelog: skip` forces a commit out of the changelog regardless of type.
- If both are present, `changelog: skip` wins.

## Releasing

Ask the user what version to bump to. Read the current version from `Cargo.toml`, then offer three options showing the
resulting version for each:

- Bump bugfix (e.g. 0.1.0 -> 0.1.1)
- Bump minor, reset bugfix (e.g. 0.1.1 -> 0.2.0)
- Bump major, reset minor+bugfix (e.g. 0.2.0 -> 1.0.0)

Then proceed:

1. Ensure you're on a fresh main with a clean working copy: `gt sync --all`, `gt checkout main`, then verify
   `git status` shows no uncommitted or untracked changes. Abort if dirty.
2. Set the version in `Cargo.toml`.
3. Refresh the lockfile: `cargo update --workspace`
4. Validate lockfile consistency: `cargo metadata --format-version 1 --locked > /dev/null`
5. Generate the changelog: `git-cliff --tag "v$VERSION" -o CHANGELOG.md`
6. Run `dprint fmt` to fix any formatting issues in the generated changelog.
7. Verify the changelog heading exists: `rg -n "^## \[$VERSION\]" CHANGELOG.md`
8. Create a release PR with commit message `chore: release $VERSION`. The PR must include `Cargo.toml`, `Cargo.lock`,
   and `CHANGELOG.md`.
9. **Stop and explicitly ask the user for confirmation before merging and tagging.** Do not silently wait -- tell the
   user you are ready to merge and tag, and ask them to confirm.
10. Merge the PR: `gh pr merge <number> --squash`
11. Sync and checkout main: `gt sync --all`, `gt checkout main`.
12. Tag the merge commit and push: `git tag v$VERSION && git push origin v$VERSION`
13. Watch the Release workflow: `gh run watch <run-id>`. Confirm it succeeds (dist plan, release-plan tests, artifact
    builds) and that the GitHub release has the four `saltybox-<target>.tar.xz` archives attached.
14. Hand the tag to the tap: in `scode/homebrew-dist-tap`, run `cargo xtask update saltybox --tag v$VERSION` and open a
    PR there. This requires the tap to have registered `saltybox` in its `pull.toml`; the command fails otherwise.
    `brew upgrade` will not see the release until that tap PR merges. Never re-upload or replace assets on a published
    tag: the tap records the archive hashes and treats changed bytes as an integrity error.

### Preflight Checklist (One-Time Per Repository)

1. Initialize git-cliff config if `cliff.toml` is missing: `git cliff --init keepachangelog`
2. Ensure `dist-workspace.toml` has `plan-jobs = ["./release-plan-tests"]` and `allow-dirty = ["ci"]`, and has no `tap`,
   no `publish-jobs`, and no `homebrew` in `installers`. The Homebrew formula is pulled and reviewed in
   `scode/homebrew-dist-tap`, not pushed from this repository.
3. Ensure the archive contract the tap consumes is intact: `targets` is exactly the four in `dist-workspace.toml`, and
   `dist plan` lists one `saltybox-<target>.tar.xz` per target containing only the `saltybox` binary plus `README.md`,
   `CHANGELOG.md`, and `LICENSE`.
4. Ensure `.github/workflows/release.yml` is generated by dist, using the exact `cargo-dist-version` pinned in
   `dist-workspace.toml` (a newer dist on `PATH` produces spurious diffs), and uses no secret other than `GITHUB_TOKEN`.
   After generation, keep the local permission hardening: the workflow-level `contents` permission must be `read`, and
   only the tag-gated `host` job may request `contents: write`.
5. Ensure `.github/workflows/conventional-commit-pr-title.yml` exists.
6. Ensure `cliff.toml` exists and is configured for Conventional Commit parsing.
